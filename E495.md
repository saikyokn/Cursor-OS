# ThinkPad E495 bring-up — CursorOS R3V63

（リリース ZIP: `dist/CursorOS-R3V63.zip`）

Target: **Lenovo ThinkPad E495** (AMD Ryzen 5 3500U / Picasso, Vega 8 `15D8`).

## Flash (dual-boot safe)

1. Build or unzip `dist/CursorOS-R3V63.zip`.
2. From the live image (USB/QEMU) or Windows, copy `saikyokn.efi` into an ESP, e.g.  
   `\EFI\CURSOROS\BOOTX64.EFI` (or use in-OS `install esp YES`).
3. Firmware boot menu → pick CursorOS. Secure Boot: enroll `secureboot/cursoros.cer` via MokManager once if needed.
4. **Do not** run `install wipe YES` on a Windows disk.

## After boot — checklist

| Step | Command / action | Expect |
|------|------------------|--------|
| 1 | Boot log shows `boot: realhw E495 path` | Paging path OK |
| 2 | `gpu` / `gpu amd` | Picasso / Vega 8, shadow or GOP |
| 3 | `gpu anim` | Rect moves (WB shadow → UC GOP) |
| 4 | Move TrackPoint / pad | Cursor moves |
| 5 | `mouse` | Look at `bat=` `ack=` `rx=` `heur=` `xhci_hid=` |
| 6 | If dead: `mouse init` then move pad, `mouse` again | `rx`/`heur` should rise |
| 7 | USB mouse: plug in → `xhci init` → move → `mouse` | `xhci_hid` rises |
| 8 | `gui` | Desktop + taskbar |

### Reading `mouse` status

| Field | Meaning |
|-------|---------|
| `bat=1` | PS/2 device answered reset (0xAA) |
| `ack=` | How many 0xFA ACKs during init (want ≥2) |
| `auxT=0x00` | Controller aux test OK |
| `irq=` | IRQ12 count — **E495 needs this >0** (QEMU also sets status bit5; E495 often does not) |
| `rx=` | Bytes accepted as mouse |
| `xhci_hid=` | USB HID mouse reports |

QEMU mouse works because virt/std PS/2 sets **status bit5** and IRQ12 cleanly.  
E495 AMD FCH often clears bit5. Workarounds:

1. Type `gui` — on the **desktop** (no notepad focus), unmarked PS/2 mouse bytes are accepted.
2. IRQ12 path still preferred when it fires; IOAPIC polarity is auto-retried.
3. **USB mouse**: plug in → `xhci init` → move → `mouse` (`xhci_hid` should rise).

Console / notepad stay strict so Enter / Backspace keep working.

## Display note

E495 has **no virtio**. Scanout stays **firmware GOP**.  
`gpu nogop` is for QEMU only — on E495 it correctly refuses. Use `gpu anim` / normal GUI (shadow present).

## Known gaps on this machine

- Built-in pad may be I2C-only on some units → USB mouse
- No amdgpu DC modeset (MMIO poke can hang)
- Network: onboard **Realtek RTL8168/8111** (`rtl8169` driver). QEMU still uses e1000.
- `install wipe` only on empty NVMe

## Rebuild

```powershell
cd bin
mingw32-make all
mingw32-make user-apps
python prepare_fsimg.py fs.img fs --compact --skip-models
python prepare_fsimg.py nvme.img fs --no-esp --compact --skip-models
python package_release.py
```
